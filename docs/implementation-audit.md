# PLAN.md implementation audit

## Editor update — 29 October 2026

The shared catalog now contains 19 categories (18 procedural choices and a custom-object path), including wardrobe/almirah, dressing table, wall mirror, split AC, ceiling fan, study desk, bedside table, bookshelf, shoe rack, TV unit and refrigerator. Web/native libraries support search aliases, room/use filters, full labels, editable prior dimensions and mounting badges. Box/Board presets support unusual items. Mounting/elevation survives serialization/migration; actual ceiling height positions ceiling fixtures; collision, door/window clearance and standing-volume checks account for height. The refrigerator class is supported by the existing COCO checkpoint and is now retained by the server filter; the other new categories are available for manual selection/correction, without claiming new learned recognition.

APK rebuilding is postponed at the user's request. No backend servers or learned-model inference were started for the catalog work.

Source changes add multiple independently positioned doors/windows to the web editor, preserve them through legacy/v2 migrations and JSON/SVG exports, and add hinged panels with per-opening angles, hinge sides and inward/outward direction in both renderers. Furniture supports drag rotation, degree input, preview and one undoable commit per completed gesture. Furniture clicks now consume their own hit event so the floor cannot immediately clear selection.

Web/native TypeScript and the domain regression suite were checked. The current environment blocks browser process socket operations, so the new browser click/touch replay could not execute; the regression script is `scripts/verify-selection.cjs`. No new physical-device acceptance run or Android APK rebuild is claimed. Backend services were not started for this work.

The backend placeholder room proposal has now been replaced by actual raw-metric-depth backprojection, floor-plane and vertical-wall RANSAC, dominant-wall alignment, a partial visible-floor rectangle and an image-to-floor homography. Boundary edges distinguish supported walls from view limits. Missing/heuristic/degenerate evidence returns no dimensions or fake corners. Web/native source now expose explicit draft review, two-point known-floor-length calibration, optional measured dimensions and deliberate application without resizing furniture or automatically replacing measurements/openings. Analysis image resizing preserves camera, pixel and homography coordinates. See [reconstruction method and limits](reconstruction-method.md).

This is a first geometry implementation, not a validated full-room scan. Room height and automatic door/window extraction remain absent; multiple photographs are not yet jointly fused. The current run passed 85 JavaScript behavior cases, 30 Python geometry/route-function/IP cases, and web/native/API/worker TypeScript checks. A cross-language check passes an actual Python proposal into the TypeScript apply operation and corrects deliberately biased depth with an independent length. These runs used synthetic inputs and mocked inference, with no learned weights loaded, servers or APK rebuild. Existing HTTP TestClient checks could not complete in this restricted environment (event-loop thread wakeup hung); route functions and Pydantic contracts were tested directly instead. New UI gestures and real-photo reconstruction still need runtime/device evaluation.

## Verification recorded

- Web, Android, API and worker TypeScript checks.
- 42 JavaScript cases across shared-domain/legacy regression files, including identity, shared dimensions, fixtures, containment, history, source coordinates, calibration and forked-project references.
- 19 Python unit/HTTP tests with synthetic pixels and mocked model contracts; real models are exercised separately.
- `scripts/verify-platform.ts`: real PostgreSQL/Redis/S3 ownership, unauthorized access, CAS conflicts, image hash checks, capture finalization, idempotency, cancellation and deletion access.
- `scripts/verify-processing.ts`: real queued detection, metric-depth/raw PNG artifacts, CLAHE and Big-LaMa removal; late analysis cannot overwrite newer scene edits; output hashes match private downloads.
- `scripts/verify-ui.cjs`: production browser checks for search, drag without panels, undo/redo, explicit details, placement, layouts, export, phone-width layouts, extraction, creation/reopen, missing rooms and honest service errors.
- Android release APK builds for ARM64 and x86_64. Android 15 emulator opens the app and the procedural scene; view switching, tray selection, confirmed placement, movement and forced-restart persistence have been exercised. Native gallery import, private source upload, server-specific sync and completed model analysis also ran through the installed APK.
- Exact model provenance and observed smoke outputs: `services/vision/model-manifest.json`, `reports/model-smoke.json`, `reports/depth-smoke.json`. Recorded latency is from this host and is not a phone-performance target.

No physical phone was attached during this work. Real-room accuracy, camera behavior, independent quality benchmarks and operational pilot acceptance remain explicitly open. No claim is made that client failures are impossible; bounded validation, actionable errors, saved drafts, retry/cancel paths and a plan-view fallback reduce their impact.
